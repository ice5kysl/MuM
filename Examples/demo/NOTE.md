# 为什么预览不用 Web 视图

这是个技术选型记录。

## 备选方案

**WKWebView + marked.js**：渲染能力和排版自由度最高，数学公式、Mermaid、
任意 CSS 主题都是现成的。代价是每个窗口多一个 Web 内容进程（约 40MB），
以及一次「Markdown → HTML → 布局」的往返。

**原生 NSTextView + cmark-gfm**：解析后直接构造 `NSAttributedString`。
文本选中、⌘F 查找、三指查词、VoiceOver、系统级字体缩放全部免费获得 ——
这些能力在 Web 方案里要一个个手工补回来，而且很难做对。

## 结论

选了后者。理由是 MuM 的定位是「快速看一眼 Markdown」，而不是「排版工具」。
在这个定位下，**没有 Web 进程**带来的启动速度和内存优势，比多支持几种
富文本语法更重要。

需要补的排版能力（引用竖线、分隔线、标题下划线）用 `NSLayoutManager` 拿
段落矩形后手工绘制，一共不到 60 行。
